# Retomada sem duplicação

## Antes de retomar

Ler ledger, cursor, intents, aceites, receipts e inventário atual de abas. Restaurar a documentação da ferramenta quando necessário. Renovar prova de identidade ativa antes de arquivo ou clique final, especialmente após pausa, compactação ou recuperação de controle.

| Situação | Conduta |
|---|---|
| CUA indisponível | Recuperar apenas o controle permitido; preservar Chrome, sessão e última aba. Se não voltar, registrar bloqueio acionável |
| Disco ausente | Preservar plano e histórico; pedir reconexão, sem substituir pelo mesmo vídeo de outra pasta |
| Upload lento | Inspecionar progresso/erro e controles existentes. Não retransmitir por timeout |
| Campo de data/hora errado | Corrigir apenas o campo antes do commit; conferir valor real e fuso |
| Aceite salvo, fila atrasada | Reabrir fila/detalhe por leitura e conferir depois. Não clicar Programar novamente |
| Identidade mudou inesperadamente | Parar transmissão, revalidar perfil e verificar uso paralelo do Facebook |
| Verificação de identidade/desafio | Usuário resolve pela UI; não contornar. Reconciliar o item antes de retomar |
| Recomendações suspensas | Guardar evidência e aplicar arquivo/pausa local aprovada, preservando histórico |
| Som em novas abas | Usar somente controles documentados/autorizados. Não declarar muting persistente sem comprovação; preservar abas pessoais e o áudio geral do computador |
| Rename/movimento falhou | Corrigir caminho/hash do registro existente; não repostar |
| Horário perdido | Comunicar; compensação requer pedido específico e novo plano sem duplicação |

Cancelamento de upload não confirmado exige inspeção concreta. Somente se não houve ready/commit/aceite, o compositor tiver sido cancelado pela UI e a fila atual comprovar ausência do horário, pode-se avaliar recuperação supervisionada do MESMO SHA/slot/intent, com autorização apropriada, novas provas e tentativa original preservada. Isso não é uma política de retry automático.

Publicações falhas já presentes na Meta devem ser tratadas pela operação nativa apropriada quando o usuário autorizar. Se ele publicou um item manualmente, identificar esse item externamente e preservá-lo antes de reprogramar os restantes. Não deduzir pela posição da lista. Reprogramar não exige reenviar arquivo; guardar ID antigo, novo horário e comprovante de cada alteração.

Se o usuário assumir o navegador, respeitar a pausa de controle. Não encerrar Chrome para retomar. O mesmo vale para a última aba produtiva, mesmo durante limpeza automática.
